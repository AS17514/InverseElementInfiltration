> 需要你做的：表现层把"同一槽位的多个表现"改为并行播放（落实架构 §四.7）

## 一、背景：后端已改了什么

**后端已完成（2026-08-12）**：`Resolver.ResolveMeleeAOE` 从"发 1 个事件（无 TargetId）"改为**逐目标发事件**——每个命中目标各发一次 `DamageDealt`，携带各自的 `TargetId`（与单目标路径同一契约）；范围无命中时补发空放事件（`TargetId=-1`，挥空动画语义）。

**你这边不改会怎样**：事件数量从 1 变 N 后，当前表现队列**逐个串行播放**——攻击者连闪 N 次 + 目标依次闪（间隔约 0.23s），视觉像"连环拳"而非"范围爆发"，且表现总时长变长。

**不会卡死**：表现完成协议完整（队列播完才发 PresentationFinished；空放已补事件）——只改后端无 bug，纯表现差异。

## 二、需要你做的：表现层"组内并行"

**依据——架构设计.md §四.7（表现时序）原文**：

```
表现组 = 一个槽位的表现集合（槽间串行、组内并行）
完成 = 组内 N 个表现全部 OnComplete（UI 侧计数聚合）
N 由表现层自定——Resolver 只发"状态变了/伤害发生"事件，不声明表现数量
```

即：**一次 AOE 攻击（一个槽位）产生的多个目标闪白，架构设计上是"一组、并行播放"**——多个目标应同时闪，攻击者闪 1 次。当前 `BattleController.PresentationLoop` 是逐事件串行播放（`yield return play()` 逐个等），未落实"组内并行"。

**建议改动（PresentationLoop，约 10 行）**：

```
现状：while (队列非空) { yield return play(); }   ← 逐个串行
改法：
  ① 帧缓冲（现有 yield return null）合并同一槽位伴随事件 → 同批为一组
  ② 组内并行：N 个表现同时启动（各自协程/DOTween 并行播放）
  ③ 计数聚合：组内 N 个全部完成（计数器归零）→ 发 PresentationFinished
  ④ 组间串行：一批完成后再处理下一批（规则层"等表现完成"机制本身已保证槽间串行）
```

**⚠️ 并行后的必做项——攻击者闪白去重**：同一槽位的多个事件会**同时**闪同一攻击者（多个协程改同一 SpriteRenderer.color 会颜色竞争闪烁）。处理：攻击者闪白只在组内执行一次（如首个事件负责攻击者动作，其余事件只闪各自目标），或攻击者闪白独立于目标闪白。

## 三、验证提示

1. 范围攻击命中多个敌人 → **同时闪白**、攻击者只闪 1 次、全部播完才切阶段
2. 范围攻击空放（范围有格但无棋子）→ 攻击者挥空动画、正常推进（不卡）
3. 单目标攻击表现与之前一致（回归）
4. 多次重开链路正常（回归）
