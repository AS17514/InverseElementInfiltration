> 日期：2026-08-19（策划确认落地方案——后端已实现，前端接表现/交互）
> 接口均在后端（GameState / Resolver / BattleFlow——`_state` / `_resolver` / `_battleFlow`）

## 一、构筑规则（牌组构筑事件——`deck_standard` 已开启）

| 规则 | 说明 |
|---|---|
| **必须选满 12 张** | 后端 `Resolver.BuildDeck` 已改"必须等于 deckSizeLimit"（原为上限型 ≤）——不满 12 返回 false（前端保持编辑态） |
| **可重复** | `allowDuplicate: true`（已开启——左键加/右键减逻辑前端已有） |
| **升变 ≤ 初始** | `promoteLimitByInitial: true`（已开启——按价值档位计数；后端强校验 + 前端 tag 已有） |
| 价值上限 | `totalValueLimit: 30` 保留（⚠️ 与"满 12 + 不带初始"的冲突待策划定夺——12 张部署牌价值 ≥48 无法构筑） |

**前端注意**：确认按钮若按"数量 < 上限"允许确认，需改为**数量 == 12** 才可确认（后端已强制，前端给明确提示更好）。

## 二、抽牌堆（新概念，2026-08-19）

```
构筑 12 张牌组
  ├─ 初始种类 → 开局 Placement 必须全部摆完（现有校验）
  └─ 部署 + 升变种类 → 抽牌堆（GameState.DrawPile）
        ├─ 第一回合开始：自动抽 4 张 → 手牌（后端自动，发 HandChanged）
        └─ 玩家行动：1 AP 抽 1 张 → 手牌（抽牌堆空 → 不可执行）
```

### 后端 API

| API | 说明 |
|---|---|
| `OnPlayerRequestDraw(DrawCardRequest)` | 玩家抽牌行动（1 AP）；校验 PlayerTurn + 抽牌堆非空 → 落账 + 扣 AP + `HandChanged` |
| `GameState.DrawPile` | 抽牌堆（defId 列表——前端显示剩余数量/可读） |
| `HandChanged` 事件 | 抽牌/转移/部署/升变都发（现有事件）——前端刷新手牌区 |

### 前端需要做的

1. **战斗面板加"抽牌"按钮**：调 `_battleFlow.OnPlayerRequestDraw(new DrawCardRequest())`；抽牌堆空 → 按钮置灰（或后端拒绝静默）
2. **抽牌堆显示**（剩余数量/可抽提示）——`_state.DrawPile.Count` 只读
3. **第一回合自动抽 4**：后端自动执行（发 HandChanged）——前端无需触发，只需处理手牌区刷新/入场表现
4. 手牌区现在**开局是空的**（初始种类直接摆上棋盘；部署/升变在抽牌堆）——Placement 阶段手牌区无牌属正常；第一回合开始后手牌区出现 4 张

## 三、已确认（2026-08-19）

1. **价值上限**（totalValueLimit=30）：**保留**——"不带初始构筑满 12"属极端情况（玩家必然带初始）；价值限制自然约束，不调整
2. **判负条件**：**无己方棋子 + 手牌空 + 抽牌堆空** 才判负（后端已改）；抽牌堆有牌时手牌空不判负（玩家仍可 1 AP 抽牌翻盘）——前端判负表现照旧（StateChanged/结算面板链路不变）
