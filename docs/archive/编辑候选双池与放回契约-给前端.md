# 编辑候选双池与放回契约（给前端）

> 日期：2026-08-19（第二次更新：术语规范 + 被替换模块展示两方案切换 + 6 候选事件级说明）
> 背景：双层价格模型 + 双池编辑候选模型落地。本文是后端接口契约——**先校验后执行**：后端返回 false 的操作，前端不得执行任何 UI 更改（防"后端判失败、前端照换图标"）。
> 接口均在 `EditorSession`（后端——`_editor`）。

---

## 零、术语规范（2026-08-19 强制——写给彼此的注释/文档统一用词）

| 术语 | 含义 |
|---|---|
| **行动槽（slot）** | 棋子**固有 4 个位置**——不增、不减、不删；"删槽"不存在 |
| **行动模块（module）** | 放入槽的内容（移动/攻击/效果模块）——**所有编辑操作的对象都是模块** |
| 程序 | 4 槽的内容序列（`List<Template>`；空槽 = 序列尾部，前端 4 槽常显） |

- "删除"仅出现在**替换**的内部描述中（先删旧、再添新 = 一个事务）；**模块数据永不删除**（模板库实例常驻）——回退绝对可靠（后端整程序快照撤销）

## 一、候选池查询：`GetEditCandidates(defId)`

**切换棋子时调用**，返回该棋子编辑候选池（**每个棋子看到的池不同**）：

```
候选池 = ① 外部候选（编辑事件抽取的 6 模块：移动×2/攻击×2/效果×2——RandomManager 种子相关，事件级；
          当前过渡形态 = 模板库全部外部模块）——所有棋子共见
        ∪ ② 本棋子"被替换的内置模块"（默认程序 − 当前程序差集——show 模式下展示）
```

- **前端职责**：切换棋子 → 查询该棋子候选池 → 刷新候选区 UI（外部部分各棋子基本一致；②仅当前棋子显示）
- 内置模块被替换后出现在候选池（②）；还原（全部撤回/还原单棋子）后②自然清空（后端差集推导，前端无需维护状态）

## 二、替换与放回

### 2.1 放回内置模块：`TryRestoreBuiltinModule(defId, module, targetIndex)` → bool（原 `TryPlaceBuiltinSlotBack` 更名）

**把被替换的内置模块放回棋子程序原槽位**（从候选池拖回）：

| 规则 | 说明 |
|---|---|
| **只能回原槽位** | targetIndex 必须 = 该模块在棋子默认程序中的原位置——放回不提供重排灵活性；位置不符 → 返回 false |
| **挤出语义（show 模式）** | 原槽位若被外部模块占据 → **直接挤出**（该外部模块移除——外部模块本就在候选池，无损失；UI 上该模块从槽位移回候选区） |
| **先校验后执行** | 返回 true = 落账成功（经 Resolver，进撤销栈——可还原）；**返回 false = 未改任何状态，前端不得执行拖放动画/图标更改** |
| 非被替换模块 / 非本棋子内置模块 | 返回 false |

### 2.2 替换 = 一步事务（策划"删除-插入"即此内部步骤：先删旧、再添新）

- 拖新模块到占用槽 = 替换（一个事务，经 Resolver 落账进撤销栈）；拖到空槽 = 添加
- **被换下的模块去向（两方案——见第三节切换）**：
  - **show 模式**：外部模块始终在候选池（无需"回池"动作）；内置模块 → 进候选池 ②（隐藏格）可再次放回
  - **hide 模式**：被换下的模块（外部 + 内置）**候选区直接隐藏**——不再可选；回退靠**撤销/还原**（数据保留，撤销恢复展示）

## 三、展示策略开关（两方案切换，2026-08-19）

后端提供**两套行为**，通过配置切换（前端无需读开关——`GetEditCandidates`/操作结果已按开关过滤；但 UI 表现有差异，见下）：

| | show（我们原设想——现有行为） | hide（策划方案——直接隐藏） |
|---|---|---|
| 被替换的内置模块 | 候选池展示（②隐藏格）→ 可放回 | 候选区**不可见**（无放回操作） |
| 被替换的外部模块 | 始终在候选池（本就在池） | 本棋子候选区**不可见**（隐藏标记，存档级） |
| 回退 | 放回 API + 撤销 | **仅撤销/还原**（快照恢复展示） |
| 配置 | `replacedModuleVisibility: "show"` | `replacedModuleVisibility: "hide"` |

- 配置位置：`Assets/Data/Configs/edit-config.json`（后端读取；默认 show）
- **前端 UI 表现差异**：hide 模式下替换/移除时，被换下模块**无"回池动画"**（候选区直接不显示）；show 模式有（现有逻辑）
- **删除/隐藏 ≠ 数据删除**：模块数据永远保留（模板库常驻 + 快照撤销）——切换开关不丢任何数据

## 四、前端现状差距（接契约时注意——2026-08-19 查证）

- 当前前端：默认程序**前 N 槽锁定**（拖入锁定槽直接拒绝）→ 玩家只能往空槽添加、**不能替换/重排默认模块**——与"编辑棋子程序（4 槽重排）""填入/替换"及本契约的放回/替换冲突
- **接本契约时需处理**（待前端同学确认）：解锁默认模块槽（允许替换/重排）或明确新的锁定语义

## 五、移除（拖出空白）

- 拖出槽位到空白 = **移除模块**（程序编辑，经 Resolver 落账）
- 被移除模块去向：外部模块无损失（本就在候选池）；内置模块 → show：候选池② / hide：隐藏
- 锁定槽不可移除（接契约解锁后同上述）

## 六、编辑事件流程（事件级——流程落地时生效，当前过渡）

- 编辑事件触发（`EditProgram` 效果执行）：后端**自动抽取**并写 `GameState.EditCandidates`（三选一棋子，defId ≤3）与 `GameState.EditModuleCandidates`（6 候选模块）→ 发 **`EditCandidatesDrawn`** 事件（2026-08-19 新增）→ **前端显示三选一面板**（从 3 个未修改基础棋子选 1）
- **`ConfirmEditPiece(defId)` → bool**（新增 API）：校验所选棋子 ∈ 本次事件候选——true 后前端走现有流程（`BeginEdit` + 打开编辑面板，候选 = `GetEditCandidates` ①部分 = 6 候选模块）
- 候选抽取规则：三选一 = 未修改棋子（无编辑差异）按类型（初始/部署/升变）各随机 1；6 候选 = 移动/攻击/效果各随机 2（RandomManager 种子相关——可复现）
- `GetEditCandidates` 的①部分 = 事件候选（当前过渡 = 模板库全部外部模块）
- 前端交互（三选一面板）由前端实现；后端提供抽取与查询

## 七、事件

- 落账成功 → 后端发 `ProgramEdited`（现有事件）→ 前端刷新槽位/候选区/卡面（现有链路）
- 候选池变化无独立事件——**切换棋子后主动查询**（GetEditCandidates）刷新
