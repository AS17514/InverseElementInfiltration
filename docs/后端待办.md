## 1. 敌方单位攻击/移动方向未做阵营反向

**现象**：敌方单位（如短弓手）选中后显示的攻击范围是朝棋盘上方（远离玩家）——敌方在上方部署区（y 6~7），`AttackTemplate.directions = Up` 直射 3 格，范围全在敌方身后，永远打不到玩家。视觉上表现为"敌方和我方同向、向后射箭"。

**根因**：`BoardRules.GetAttackableCells`（以及 `GetLegalMoves`）把 `template.directions` / `MoveStep.direction` 直接按**棋盘格世界方向**解析（`DirectionToVector(Up) = (0,1)`），未按棋子阵营区分。数据层敌我共用同一套 PieceDef（基础牌组 12 张，升变牌玩家也可获得），**不能靠改数据**按阵营区分方向。

**建议修法（方案 A，最小改动）**：查询层对 `side == Enemy` 的棋子做方向集镜像翻转：

```
Up ↔ Down，Left ↔ Right，UpLeft ↔ DownRight，UpRight ↔ DownLeft
```

即敌方查询攻击/移动范围时，方向集自动反向（朝向我方），玩家侧保持不变。

- 位置：`Assets/_Project/Gameplay/BoardRules.cs` — `GetAttackableCells`（方向循环处）、`GetLegalMoves`（MoveStep.direction 处）
- 改动量：约 20 行，前后端共享代码一次生效

**备选方案 B（方向相对 facing）**：directions 改为相对棋子 facing 旋转（语义最正，但改动面大：攻击+移动+AI 目标选择全链路，且 `PieceInstance` 构造已按阵营翻转 facing——若采用本方案，facing 翻转改动正好配套）。是否采纳由后端定。

**附带说明**：`PieceInstance.cs` 构造已实现敌方初始 `facing` 翻转（Up↔Down），目前 facing 字段无战斗逻辑消费（仅入存档）——如后端采用方案 B 可直接利用。

**✅ 已修复（2026-08-06，方案 B 采纳）**：`BoardRules.RotateVector`——directions/MoveStep.direction 语义定为"相对棋子 facing（正前方）"，解析时按 facing 旋转到世界方向（Up 无旋转/Down 180°/Left 90°/Right -90°）；GetAttackableCells 与 GetLegalMoves 均应用；敌方 facing 已镜像（Up↔Down）→ 方向自动朝向我方。方向语义文档已同步（架构设计.md §六）。

## 3. 战斗结束后误判胜利（失败后又出现胜利日志）

**现象**：玩家失败（EndBattle → GameOver）后约 116ms，又触发一次 GameOver + 胜利判定（日志："战斗结束（失败）→ 返回主菜单"后接"战斗结束（胜利）→ 返回主菜单"）。

**根因**（三个叠加缺陷）：
1. **Bootstrap.BackToMainMenu 在规则层事件回调内同步 ResetForNewRun**——把 GameState.Phase 重置回 Placement，破坏 CheckVictory 开头的 `Phase == GameOver` 防御（BattleFlow.cs 约 590 行）
2. **AllWavesDeployed() 依赖 BattleFlow 字段 `_deployedWaveIndex`**——只被 StartBattle 重置，ResetForNewRun 不清 → 残留"3 波已部署" → 棋盘清空后误判全灭胜利
3. **ResolveEnemyTurn 的 foreach 无 GameOver 中断**——失败后仍处理剩余请求，每请求末尾 CheckVictory 重新判定

**触发链**：失败 EndBattle → OnStateChanged 回调 → BackToMainMenu → ResetForNewRun（Phase=Placement）→ 返回 ResolveEnemyTurn 剩余请求循环 → ProcessRequest 阶段校验被拒但末尾 CheckVictory 仍执行 → IsPlayerDefeated=false（手牌已填 12）+ AllWavesDeployed=true（残留）+ IsEnemyWiped=true（棋盘空）→ 判胜。

**修复建议**：
- **C（根本）**：BattleFlow 加 `_battleEnded` 标志——EndBattle 置 true / StartBattle 清 false；CheckVictory 开头 `if (_battleEnded || Phase == GameOver) return;`（约 3 行）
- **D（防御）**：ResolveEnemyTurn foreach 加 `if (_state.Phase == BattlePhase.GameOver) break;`
- **B（结构性，可排期）**：BackToMainMenu 不在规则层调用栈内同步重置状态（延后一帧）

**归属**：规则层时序漏洞（BattleFlow），共享代码。

**✅ 已修复（2026-08-06）**：
- **C（根本）已实施**：`BattleFlow._battleEnded` 标志——EndBattle 置 true / StartBattle 清 false；CheckVictory 双重防御（`_battleEnded || Phase == GameOver`）——标志位不可被 ResetForNewRun 重置，根治"重置破坏防御"
- **D（防御）已实施**：`ResolveEnemyTurn` foreach 加终态 break（`Phase == GameOver || _battleEnded`）
- **B（结构性）未做，排期**：BackToMainMenu 延后一帧——涉及 Bootstrap 回调时序与 UI 协作，另行排期
