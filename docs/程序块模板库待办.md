# 程序块模板库待办（独立程序块定义缺失）

> 记录人：UI 侧（前端）
> 关联：docs/后端待办.md 第 2 条（程序块编号体系，✅ 编号已落地）

---

## 现状（2026-08-09 排查结论）

**测试数据中没有"独立程序块/模板定义"**——全部程序块都内联在棋子数据里：

- `Assets/Data/Pieces/*.json`：12 个棋子各含 modules（内联程序块），**无独立模板文件**
- `Assets/Settings/`：29 个 SO 资产全部是 PieceDef/RelicDef/EventPool/EventDefinition/MapConfig/FloorConfig/SpecialAbilityDef——**无 Template 类型资产**
- `ConfigImporter`：只导棋子（模板随棋子资产生成，不产独立资产）
- 代码层：无模板注册表（TemplateRegistry/TemplateLibrary 均不存在）

**实际模板变体**：12 棋子程序块去重后 **21 种**（Move 17 变体 + Attack 6 变体含共用）——编辑界面程序库目前只能用它。

## 问题

1. **编辑界面模板库被限制在"棋子自带模板"**——玩家只能把已有模板编排进槽位，无法使用超出自带范围的模板（如事件文案提到的"攻击[后·左·右选一格]"就不在数据里）
2. **事件 `edit_standard` 文案与数据不一致**："移动[正前方1格] / 攻击[后·左·右选一格]"候选模板**无数据定义**——按文案应该能编排这些模板，但数据里没有

## 待后端规划

- [ ] **独立模板库数据**：新增模板定义（JSON + 导入器 + Template 注册/资产），编辑界面可编排范围超出自带模板
- [ ] **候选模板数据补全**：edit_standard 事件文案承诺的"移动[正前方1格] / 攻击[后·左·右选一格]"补进模板库
- [ ] 与程序块编号体系（todo #2）合并规划——编号落地后模板库 = "编号 → Template 定义"映射表
