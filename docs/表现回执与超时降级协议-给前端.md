# 表现回执 token 与超时降级（给前端）

> 日期：2026-08-21；状态：后端已实现——前端需按本节对接回执；旧行为（不带 token 回执）仍兼容（过渡期不会卡死）
> 关联：docs/后端进度说明-给前端.md、表现层组内并行契约

---

## 一、为什么加 token（背景）

表现同步此前是"前端播完→发全局完成事件→后端讲一槽"——**串行假设**（一次只播一个）下顺序即身份。但存在：多表现并行（AOE 组内并行）、迟到/重复回执、无超时兜底（表现卡死=规则层永卡）。为此后端给每次表现等待发**令牌**，回执必须对令牌。

## 二、后端行为（已实现）

| 点 | 行为 |
|---|---|
| 等待开始 | 后端每次表现等待分配 token = `(sessionId, actionId)`（`battleSessionId`=当前战斗，`actionId`=战斗内递增） |
| 暴露读取 | `BattleFlow.CurrentPresentationToken`（前端播完动画后读取——等待中返回当前 token；未等待/已结束 = actionId -1） |
| 回执校验 | 收到 `PresentationFinished(PresentationInfo{sessionId, actionId})`：匹配当前等待 → 推进一步；不匹配（迟到/重复/跨战斗）→ **忽略 + 日志**（不误认） |
| 超时降级 | 等待超 `PresentationTimeoutSeconds`（默认 3s）无回执 → **放行（推进）+ `LogError` 显著警告 + 记入存档诊断**——"超时=前端表现疑似异常，需排查"，**不是静默容忍** |

## 三、前端需要做的事（对接）

1. **回执带 token**：前端每播完一组表现（含 AOE 组内并行——**整组播完聚合回执一次**），读取 token 并原样带回：
   ```csharp
   var token = _flow.CurrentPresentationToken; // (sessionId, actionId)
   EventCenter.Instance.EventTrigger(GameEvent.PresentationFinished,
       new PresentationInfo { SessionId = token.sessionId, ActionId = token.actionId });
   ```
   - **播完与跳过（设置/低性能）都算完成，都要回执**
   - 未等待时读到 actionId=-1 → 可发也可不发（后端会忽略不匹配）
2. **聚合回执**：一次落账等待 = 一组表现（多目标并行闪白等）——**必须全部播完再回执一次**（不能逐目标回执 N 次）
3. **超时预警排查**：后端 `LogError("[BattleFlow] 表现回执超时降级...")` = 前端表现链路有问题（某次没回执/回执太慢）——查对应 session/action 的动画
4. **无需改动即可兼容**：旧代码（不带 token 的空回执）仍被接受（过渡期）——但建议尽快按 1-2 对接（否则并行/迟到场景无法精确同步）

## 四、超时记录的存档查阅（diagnostics）

- 每次超时降级后端写一条到存档 JSON：
  ```json
  "diagnostics": { "presentationTimeouts": [
    { "SessionId": 3, "ActionId": 27, "WaitMs": 3100, "Phase": "PlayerTurn", "At": "2026-08-21T15:04:12" }
  ]}
  ```
  （环形缓冲，最多 20 条——只写不读，不影响游戏进度）
- 位置：`save.json`（Windows：`%USERPROFILE%\AppData\LocalLow\<公司名>\<项目名>\save.json`）；历史档 `save_history_<时间戳>.json`
- **有内容 = 发生过超时**：SessionId 连续多条 / WaitMs 明显大于正常动画时长 → 该场表现链路有问题（排查方向：回执没发/发太慢/聚合缺漏）
- 空数组 = 无超时（正常）

## 五、取消/禁用（如前端认为降级机制不好）

后端 `BattleFlow.PresentationTimeoutSeconds` 置 0 或负 = **完全禁用超时降级**（回到"无限等"旧行为）——前端可在开发期/调试改这一处（或后续做成设置开关再议）。
