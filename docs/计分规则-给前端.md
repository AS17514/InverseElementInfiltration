## 〇、策划原文（2026-08-19 用户口述——原文标注）

> **以下为策划原文**（用户原话，逐字保留）：
>
> 然后后续关卡的计分规则是这样子。
>
> 计分规则：
> 按回合计分，每个回合结束时（对手的该回合结束，如果对方无法行动则直接计算），按基础分数乘以倍率获得分数，然后基础得分清零，倍率变为1（如果没有特殊效果的话）
> 每个波次统计该波次回合获得的得分之和，看波次得分是否达标（第一关和第四关无需判断）
> 所有分数将被加算在总得分中，看最终得分是否达标（第一关无需判断）
>
> 固定得分规则：
> 当敌方的棋子被击败后，基础得分+那个棋子的价值

## 一、规则（玩家侧）

| 环节 | 规则 |
|---|---|
| **固定得分** | 敌方棋子被击败 → **基础得分 + 该棋子价值** |
| **回合结算** | 每个回合结束时（敌方回合结束；对方无法行动 → 直接结算）→ **得分 = 基础分 × 倍率** → 加算入总得分（本关）并计入本波次统计 → **基础分清零、倍率复位 1** |
| **倍率** | 默认 1（特殊效果可修改——来源未设计，字段预留） |
| **本关口径** | 总得分**不跨关累计**（每关从 0 开始——后端 ResetForBattle 已清） |
| **第 1 关** | **完全不结算**（WipeOut 纯战斗关——无得分） |

## 二、后端接口/事件

- `GameState.BaseScore`（基础分——击杀积累，只读展示可选）、`GameState.ScoreMultiplier`（倍率）、`GameState.PlayerScore`（本关总得分——结算后值）
- 结算时发 `StateChanged`（携带 "score"）——前端可刷新得分显示（**回合末变化**——回合中击杀时总得分静止）
- 敌方侧（EnemyScore）击杀直加——玩家计分不对称（AI 测试员——已知取舍）

## 三、前端可做

1. **总得分显示**（战斗面板/结算面板）：读 `PlayerScore`——回合末结算后跳变（显示节奏按此）
2. **基础分显示**（可选）：读 `BaseScore`——击杀时 +价值（回合中可见积累）
3. **倍率显示**（可选）：读 `ScoreMultiplier`——默认 1（特殊效果落地后有意义）
4. 结算面板：得分 = 本关值（PlayerScore——已按本关口径）

## 四、达标（后端判定——前端只展示）

- **波次达标**：第 2/3 关——每波结算得分之和 ≥ 该波达标线（WaveDef.waveScoreTarget——数值策划回填；第 1/4 关无需）
- **总得分达标**：第 2/3/4 关——PlayerScore ≥ targetScore（数值策划回填；第 1 关无需）
- 第 2-4 关配置（victoryRule/targetScore/达标线/阵容）策划输入后生效
