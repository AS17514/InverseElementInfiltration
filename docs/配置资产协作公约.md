# 配置资产协作公约（2026-08-09）

> 背景：模板库合并时，双方独立生成同一批 Tpl 资产（GUID 随机分配，两边不同）→ 43 个冲突。
> 目的：避免"派生物（.asset + .meta）被多人独立生成提交"导致的 GUID 分叉。
> 适用范围：Assets/Settings/ 下全部配置资产（棋子/能力/关卡/地图/事件/遗物/模板）。

---

## 核心思想

```
JSON = 人写格式（权威源——可 diff、可审、无 GUID）
资产 = 派生物（机器生成——GUID 随机、不可手动 diff）
→ 派生物【单一角色生成提交】；其他人只 pull 消费
```

## 公约 6 条

```
1.【单一生成者】Assets/Settings/ 下 .asset 一律由【后端】统一生成并提交；
   UI 侧只 pull 使用，不自行跑导入器生成资产。
   本地测试生成可以，但【不得提交】生成物；若必须提交——先 pull 并确认仓库无同名资产。

2.【提交前检查】git status 出现 Assets/Settings/**/*.asset 或 .meta 的
   未跟踪/修改时，先查 git ls-files 是否已有同名——有则用仓库版本，不覆盖。

3.【生成前先 pull】任何导入器/收集工具运行前先 pull 最新
   （基于最新生成，减少分叉）。

4.【冲突标准】资产/meta 同名冲突 → 取"被场景/预制体引用"的那边；
   两边均未被引用 → 取任一边（同一 JSON 生成，内容等价）。
   （2026-08-09 实例：Tpl 资产冲突取 ours——因为 Bootstrap.prefab 引用我们的 GUID）

5.【JSON 是权威源】一切配置修改改 JSON + 跑导入器；资产不手动改。
   导入器保持增量模式（不删旧建新——GUID 不变，场景引用不断）。

6.【工具归属】导入器/收集工具由后端维护；新增功能先对齐再实现。
```

## 检查清单（提交前）

```
[ ] git status 无 Assets/Settings/** 未跟踪 .asset/.meta（或已确认是新增且仓库无同名）
[ ] 导入器运行前已 pull 最新
[ ] 资产修改均来自"改 JSON + 跑导入器"（无手动编辑资产）
[ ] 提交信息注明资产来源（如"导入生成"）
```

## 常见冲突处理

| 情况 | 处理 |
|---|---|
| both added 同名资产/meta | 取被引用方；都没被引用取任一边 |
| both modified 资产 | 说明双方都改过资产——以 JSON 重新生成为准（跑导入器覆盖） |
| both modified 场景（Main.unity） | 手动合并（保留双方 override——引用仓库已提交资产的 GUID） |

## 附：美术/音频走 LFS 的利弊分析（2026-08-21——决策参考）

> 现状：README 协作约定写的是"美术/音频二进制走 LFS 自动处理"，但实际 **LFS 未启用**：
> `.gitattributes` 没有 LFS 规则、`git lfs` 未 install、`git lfs ls-files` 为空——美术/音频目前是**普通 git 入库**（当前美术量小，约 2~3MB，短期无实质影响）。

### 启用 LFS 的利

1. **仓库体积稳定**：美术/音频是大二进制且常改——LFS 让 git 本体只存指针，改图/加图不会让 `.git` 随每次版本无限膨胀
2. **历史可回收**：即使后来删除/覆盖某资源，旧版本只占 LFS 对象（不撑大 git 历史）
3. **克隆/拉取快**：新成员 clone 只拉指针 + 按需取真实文件（对代码拉取友好）
4. **代码与二进制分离**：二进制变动不拖累代码 diff/review 体感

### 启用 LFS 的弊 / 成本

1. **切换成本高**：已入库的美术需要 `git lfs migrate` 重写历史（牵动全员换基/或迁新库）——当前历史里的二进制不会自动变小
2. **依赖 GitHub LFS 配额**：免费配额有限（存储 ~1GB + 每月流量）——美术/音频上来后可能超配额需付费
3. **访问依赖 + 客户端**：需要所有成员装 `git lfs` 客户端、远端 LFS 服务器可达；离线/内网拉不到真实文件
4. **"Download ZIP" 拿不到 LFS 文件**：GitHub 的 ZIP 下载**不含 LFS 真实文件**（只会是指针文本）——对"通过链接下载即玩"完全不利（已有外部同学下载不显示美术的先例，若再加 LFS 会双倍踩坑）
5. **纪律成本**：`.gitattributes` 规则 + `git lfs install` 纪律——有人忘了配 LFS，会直接把大文件怼进 git 本体
